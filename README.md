# Цифровой двойник газового промысла над АСУ ТП — прототип

Локальный прототип по ТЗ [`docs/TZ_digital_twin.md`](docs/TZ_digital_twin.md). Двойник читает
данные АСУ ТП (в прототипе — имитатор и таблицы CSV), проверяет их качество, прогоняет через
модели и правила и выдаёт уведомления оператору и рекомендации главному инженеру. Двойник только
читает: решение принимает человек и вводит его в АСУ.

Исходные материалы — в [`docs/`](docs/): ТЗ, отчёт «Датчики, модели и уведомления цифрового
месторождения» и ссылка на продольный разбор.

## Установка

Нужен Python 3.12 или новее. Работает под Windows и Linux.

```bash
python -m venv .venv
# Linux:   source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Без интернета: на машине с интернетом скачайте колёса и перенесите папку `wheels/`:

```bash
pip download -d wheels ".[dev]"                      # на машине с интернетом
pip install --no-index --find-links wheels -e ".[dev]"   # на машине без интернета
```

Колёса нужно скачивать под ту же ОС и версию Python, что и на целевой машине
(`pip download --platform win_amd64 --python-version 3.12 --only-binary=:all: ...`).

## Запуск

Сгенерировать синтетические данные с дефектами (CSV по каждому потоку и эталон `truth.json`):

```bash
field-twin-generate --out data/samples --days 3 --seed 42
```

Принять таблицы в базу двойника и получить отчёт о приёме:

```bash
field-twin-ingest data/samples/*.csv --db data/twin.sqlite
```

Под Windows вместо `*.csv` перечислите файлы или используйте PowerShell:
`field-twin-ingest (Get-ChildItem data\samples\*.csv) --db data\twin.sqlite`.

Проверить качество и очистить данные (М2), проверить правила П13 и П14, записать срабатывания в журнал:

```bash
field-twin-quality --db data/twin.sqlite
field-twin-quality --db data/twin.sqlite --now 2026-07-04T12:00:00+05:00   # свежесть на заданный момент
```

Без `--now` «сейчас» — последнее значение в данных (режим проверки архива).

Выгрузить разметку из журнала (решения человека с причинами аномалий и размеченные периоды):

```bash
field-twin-journal --db data/twin.sqlite --labels data/labels.csv --periods data/period_labels.csv
```

Без установки пакета те же команды запускаются как `python -m field_twin.simulator`,
`python -m field_twin.ingest`, `python -m field_twin.quality`, `python -m field_twin.journal` с `PYTHONPATH=src`.

Тесты:

```bash
pytest
```

## Конфигурация

| Файл | Что задаёт |
| --- | --- |
| `config/tags.yaml` | словарь параметров: потоки, объекты, параметры, единицы, интервалы, уставки |
| `config/thresholds.yaml` | пороги правил П1–П16 с источниками; `null` — порога нет в источниках |
| `config/quality.yaml` | приём (разделитель, кодировка, часовой пояс) и параметры очистки |
| `config/anomaly_reasons.yaml` | справочник причин аномалий для журнала |
| `config/simulator.yaml` | синтетика: базовые значения, интервалы, дефекты |

Пороги и параметры меняются в конфигурации без правки кода. Другая папка конфигурации —
через `--config` или переменную `FIELD_TWIN_CONFIG`.

## Формат данных

CSV длинного формата, время ISO 8601 с часовым поясом:

```
timestamp,stream,object_id,parameter,value,unit,quality,equipment_state
2026-07-01T00:00:00+05:00,wells,W-101,P_wellhead,8.01,МПа,good,run
```

- `quality`: `good`, `uncertain`, `bad`;
- `equipment_state`: `run` (работа), `stop` (остановка), `repair` (ремонт). Столбца может не быть:
  в архивах этого признака нет, его выведет модуль очистки (М2).

## Что делает этап 1

**Генератор** (`src/field_twin/simulator.py`) выдаёт все 12 потоков из раздела «Входные данные»
с их интервалами и внедряет дефекты: простои, сбойные датчики, нечисловые значения, аномальные
давления при нулевом расходе (Шевченко, Рычков); пропуски — строк без пропусков около 14 %, чаще
всего пропущена обводнённость (Печко и соавторы); шум и выбросы в рядах давления, технологические
остановки скважин с монотонным ростом давления (Савченко и соавторы); эпизоды гидратов по
признакам Сафроновой; строки с ошибками формата. Всё внедрённое записывается в `truth.json`.
Величины в синтетике выбраны в прототипе, направления изменений — по источникам.

**М1. Приём** (`src/field_twin/ingest.py`): разделитель и кодировка из настроек, время приводится
к одному поясу, проверяются обязательные поля. Строки с ошибками формата сохраняются со статусом
`error` и показываются в отчёте. Сигналы без привязки в словаре и несовпадение единиц — предупреждения.
Нечисловые значения и пропуски сохраняются как есть: их обрабатывает М2.

**М8. Журнал** (`src/field_twin/journal.py`): срабатывания моделей и правил, уведомления,
сигнализация АСУ (хранится отдельно, `source = asu`), решения человека с обязательной причиной
из справочника, размеченные периоды, флаг теневого режима, выгрузка разметки в CSV.

## Что делает этап 2

**М2. Контроль качества** (`src/field_twin/quality.py`) — конвейер Печко и соавторов, исходные
записи не меняются, результат — очищенное значение и флаги по каждой записи (таблица `clean_values`):

1. **Простои**: по признаку состояния оборудования, а если его нет — по нулевому расходу; выведенное
   состояние помечается как вычисленное (Шевченко, Рычков). Значения во время простоя не участвуют
   в статистике.
2. **Нефизичные значения** (Савченко и соавторы): нули давления и значения вне допустимого
   диапазона. Физические пределы по роли параметра — в `physical_ranges`, диапазоны конкретных
   параметров задаёт пользователь в `ranges`.
3. **Аномальное давление при нулевом расходе** (Шевченко, Рычков): во время простоя давление
   нефизично или вне 3σ рабочего режима. Скважины исключены: рост давления после остановки — физика.
4. **Три критерия по каждому параметру** (Шевченко, Рычков): разница среднего и медианы, доля
   значений в пределах 3σ, корреляция Пирсона со связанным параметром.
5. **Выбросы** за 3σ помечаются, но не удаляются. Исключение подтверждает пользователь
   (`quality.confirm_exclusion`), после чего значение уходит из очищенного ряда.
6. **Сглаживание рядов давления полиномом** (Савченко и соавторы) — выключено, пока в
   `smoothing` не заданы степень, порог и окно.
7. **Пропуски**: одиночный пропуск в строке восстанавливается линейной интерполяцией по соседним
   годным значениям и помечается; строки с несколькими пропусками только помечаются (Печко и соавторы).
8. **Свежесть**: поток устарел, если не обновлялся дольше двух своих интервалов. Если интервала
   нет в словаре, он оценивается по данным (медиана шага) и это отмечается.
9. **Усреднённые по месяцам ряды** для обновления моделей (СТО Газпром 2-3.3-1203-2020), месяц по UTC.
10. **Отчёт о качестве**: доля строк без пропусков (всего и по потокам), доля пропусков по каждому
    параметру, число пометок по каждому критерию, свежесть потоков.

**Правила** (`src/field_twin/rules.py`), срабатывания пишутся в журнал (М8):

- **П13** «Устаревшие данные» — по результату проверки свежести; адресат — оператор пульта.
- **П14** «Расхождение связанных датчиков» — корреляция Пирсона пары датчиков по окнам (2 ч,
  решение прототипа) ниже порога. **Порог `min_pearson` в источниках не задан, поэтому правило
  выключено**, пока его не задать в `config/thresholds.yaml`.

Пример данных за сутки лежит в `data/samples/`.
