# Цифровой двойник газового промысла над АСУ ТП — прототип

Локальный прототип по ТЗ [`docs/TZ_digital_twin.md`](docs/TZ_digital_twin.md). Двойник читает
данные АСУ ТП (в прототипе — имитатор и таблицы CSV), проверяет их качество, прогоняет через
модели и правила и выдаёт уведомления оператору и рекомендации главному инженеру. Двойник только
читает: решение принимает человек и вводит его в АСУ.

Исходные материалы — в [`docs/`](docs/): ТЗ, отчёт «Датчики, модели и уведомления цифрового
месторождения» и ссылка на продольный разбор. Соответствие критериям приёмки ТЗ и тестам —
[`docs/acceptance.md`](docs/acceptance.md); что осталось без ответа в источниках —
[`docs/open_questions.md`](docs/open_questions.md). Продолжение работы в новой сессии — [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Быстрый старт

```bash
pip install -r requirements-dev.txt && pip install -e .
pytest                                # 228 тестов, около полутора минут
./scripts/demo.sh                     # Windows: powershell -File scripts\demo.ps1
```

Демонстрация обучает модели на синтетике и проигрывает двое суток данных с экранами:
откройте http://127.0.0.1:8000/operator и http://127.0.0.1:8000/chief и нажмите «Включить звук».

## Установка

Нужен Python 3.12 или 3.13, 64-разрядный. Проверено под Linux; под Windows — те же пакеты
(у всех зависимостей есть готовые колёса для Windows x64). ТЗ требует работу под Windows и
РЕД ОС «Муром» без доступа в интернет (Запевалов и соавторы).

### С интернетом

Linux:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
pip install -e .
```

Windows (PowerShell):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
pip install -e .
```

### Без интернета

1. На машине **с интернетом** скачайте колёса в папку `wheels/` проекта:

   ```bash
   ./scripts/download_wheels.sh                               # для той же ОС и версии Python
   PLATFORM=win_amd64 PY=3.12 ./scripts/download_wheels.sh    # для Windows x64, Python 3.12
   PLATFORM=manylinux2014_x86_64 PY=3.12 ./scripts/download_wheels.sh   # для Linux x64 (РЕД ОС)
   ```

   Набор колёс около 215 МБ. Версии зафиксированы в `requirements.txt` и `requirements-dev.txt`.
2. Перенесите папку проекта вместе с `wheels/` на целевую машину.
3. На машине **без интернета**:

   ```bash
   ./scripts/install_offline.sh                                       # Linux, РЕД ОС
   powershell -ExecutionPolicy Bypass -File scripts\install_offline.ps1   # Windows
   ```

   Скрипт создаёт `.venv`, ставит зависимости только из `wheels/` (`--no-index`) и сам проект.
4. Проверка: `pytest`. Тест `tests/test_offline.py` дополнительно прогоняет всю цепочку с запретом
   любых сетевых соединений, кроме локальных.

Установка из `wheels/` в чистое окружение с заблокированной сетью проверена: все тесты проходят.
Экраны не загружают ничего из интернета: стили, скрипты и звуковой сигнал лежат в `web/`.

Для адаптера HYSYS на Windows дополнительно нужен `pywin32` (`pip install pywin32` или его колесо
в `wheels/`) и установленный Aspen HYSYS — см. [`docs/hysys.md`](docs/hysys.md).

## Запуск

Сгенерировать синтетические данные с дефектами (CSV по каждому потоку и эталон `truth.json`):

```bash
field-twin-generate --out data/samples --days 3 --seed 42
```

Принять таблицы в базу двойника и получить отчёт о приёме:

```bash
field-twin-ingest data/samples/*.csv --db data/twin.sqlite
```

Под Windows вместо `*.csv` перечислите файлы или используйте PowerShell:
`field-twin-ingest (Get-ChildItem data\samples\*.csv) --db data\twin.sqlite`.

Проверить качество и очистить данные (М2), проверить правила П13 и П14, записать срабатывания в журнал:

```bash
field-twin-quality --db data/twin.sqlite
field-twin-quality --db data/twin.sqlite --now 2026-07-04T12:00:00+05:00   # свежесть на заданный момент
```

Без `--now` «сейчас» — последнее значение в данных (режим проверки архива).

Обучить классификатор гидратов (М3) на синтетике с несколькими эпизодами:

```bash
field-twin-generate --out data/train --days 8 --hydrate-episodes 4
field-twin-ingest data/train/absorber.csv data/train/methanol.csv --db data/train.sqlite
field-twin-hydrates --db data/train.sqlite --truth data/train/truth.json
```

На реальных данных вместо `--truth` используются периоды, размеченные в журнале как
гидратообразование, и решения по П1 с причинами. Модель сохраняется в `data/models/hydrates.cbm`
и дальше используется циклом `field-twin-run`.

Обучить нейросети Чудина (М4) и адаптировать их на последних 30 сутках:

```bash
field-twin-chudin --synthetic-days 400            # на синтетике
field-twin-chudin --db data/twin.sqlite           # на суточных средних из базы двойника
```

Обучить модель КРН участков газопроводов (на синтетике — с пометкой во всех прогнозах):

```bash
field-twin-scc --synthetic            # или --csv выборка.csv для реальных данных
```

Проиграть архив с экранами (уведомления появляются как в реальном времени; скорость ×60 —
сутки данных за 24 минуты):

```bash
field-twin-playback data/samples/*.csv --db data/playback.sqlite --speed 60 --serve
```

Откройте http://127.0.0.1:8000/operator и http://127.0.0.1:8000/chief, нажмите «Включить звук»
(браузеры не дают странице играть звук без действия пользователя). Только сервер экранов по
готовой базе: `field-twin-serve --db data/twin.sqlite`.

Связка с АСУ ТП через имитатор (два окна терминала):

```bash
field-twin-asu-sim data/samples/*.csv --url opc.tcp://127.0.0.1:4840/asu --speed 60
field-twin-gateway --db data/twin.sqlite --url opc.tcp://127.0.0.1:4840/asu --cycles
```

Второй `--url` — резервный сервер сбора. Переход на реальную АСУ: адрес сервера и файл словаря
(`--dictionary`), без правки кода.

Полный цикл двойника — качество, геотехника, все пороговые правила, запись в журнал:

```bash
field-twin-run --db data/twin.sqlite
```

Выгрузить разметку из журнала (решения человека с причинами аномалий и размеченные периоды):

```bash
field-twin-journal --db data/twin.sqlite --labels data/labels.csv --periods data/period_labels.csv
```

Без установки пакета те же команды запускаются как `python -m field_twin.simulator`,
`python -m field_twin.ingest`, `python -m field_twin.quality`, `python -m field_twin.journal` с `PYTHONPATH=src`.

Тесты:

```bash
pytest
```

## Конфигурация

| Файл | Что задаёт |
| --- | --- |
| `config/tags.yaml` | словарь параметров: потоки, объекты, параметры, единицы, интервалы, уставки |
| `config/thresholds.yaml` | пороги правил П1–П16 с источниками; `null` — порога нет в источниках |
| `config/quality.yaml` | приём (разделитель, кодировка, часовой пояс) и параметры очистки |
| `config/anomaly_reasons.yaml` | справочник причин аномалий для журнала |
| `config/simulator.yaml` | синтетика: базовые значения, интервалы, дефекты, события для правил |
| `config/models.yaml` | М3 (гидраты), М4 (Чудин), М10 (остановки скважин) |
| `config/screens.yaml` | что показывать на экранах оператора и главного инженера |
| `config/cores.yaml` | внешние расчётные ядра (М9): какие классы подключены |
| `config/hysys.yaml` | соответствие сигналов двойника и потоков модели HYSYS |
| `config/plant_link.yaml` | стык с заводом (М11): источники данных и окна снабжения |
| `config/gateway.yaml` | шлюз АСУ (М12): серверы OPC UA, MQTT, буфер, проверка выполнения |

Пороги и параметры меняются в конфигурации без правки кода. Другая папка конфигурации —
через `--config` или переменную `FIELD_TWIN_CONFIG`.

## Формат данных

CSV длинного формата, время ISO 8601 с часовым поясом:

```
timestamp,stream,object_id,parameter,value,unit,quality,equipment_state
2026-07-01T00:00:00+05:00,wells,W-101,P_wellhead,8.01,МПа,good,run
```

- `quality`: `good`, `uncertain`, `bad`;
- `equipment_state`: `run` (работа), `stop` (остановка), `repair` (ремонт). Столбца может не быть:
  в архивах этого признака нет, его выведет модуль очистки (М2).

## Что делает этап 1

**Генератор** (`src/field_twin/simulator.py`) выдаёт все 12 потоков из раздела «Входные данные»
с их интервалами и внедряет дефекты: простои, сбойные датчики, нечисловые значения, аномальные
давления при нулевом расходе (Шевченко, Рычков); пропуски — строк без пропусков около 14 %, чаще
всего пропущена обводнённость (Печко и соавторы); шум и выбросы в рядах давления, технологические
остановки скважин с монотонным ростом давления (Савченко и соавторы); эпизоды гидратов по
признакам Сафроновой; строки с ошибками формата. Всё внедрённое записывается в `truth.json`.
Величины в синтетике выбраны в прототипе, направления изменений — по источникам.

**М1. Приём** (`src/field_twin/ingest.py`): разделитель и кодировка из настроек, время приводится
к одному поясу, проверяются обязательные поля. Строки с ошибками формата сохраняются со статусом
`error` и показываются в отчёте. Сигналы без привязки в словаре и несовпадение единиц — предупреждения.
Нечисловые значения и пропуски сохраняются как есть: их обрабатывает М2.

**М8. Журнал** (`src/field_twin/journal.py`): срабатывания моделей и правил, уведомления,
сигнализация АСУ (хранится отдельно, `source = asu`), решения человека с обязательной причиной
из справочника, размеченные периоды, флаг теневого режима, выгрузка разметки в CSV.

## Что делает этап 2

**М2. Контроль качества** (`src/field_twin/quality.py`) — конвейер Печко и соавторов, исходные
записи не меняются, результат — очищенное значение и флаги по каждой записи (таблица `clean_values`):

1. **Простои**: по признаку состояния оборудования, а если его нет — по нулевому расходу; выведенное
   состояние помечается как вычисленное (Шевченко, Рычков). Значения во время простоя не участвуют
   в статистике.
2. **Нефизичные значения** (Савченко и соавторы): нули давления и значения вне допустимого
   диапазона. Физические пределы по роли параметра — в `physical_ranges`, диапазоны конкретных
   параметров задаёт пользователь в `ranges`.
3. **Аномальное давление при нулевом расходе** (Шевченко, Рычков): во время простоя давление
   нефизично или вне 3σ рабочего режима. Скважины исключены: рост давления после остановки — физика.
4. **Три критерия по каждому параметру** (Шевченко, Рычков): разница среднего и медианы, доля
   значений в пределах 3σ, корреляция Пирсона со связанным параметром.
5. **Выбросы** за 3σ помечаются, но не удаляются. Исключение подтверждает пользователь
   (`quality.confirm_exclusion`), после чего значение уходит из очищенного ряда.
6. **Сглаживание рядов давления полиномом** (Савченко и соавторы) — выключено, пока в
   `smoothing` не заданы степень, порог и окно.
7. **Пропуски**: одиночный пропуск в строке восстанавливается линейной интерполяцией по соседним
   годным значениям и помечается; строки с несколькими пропусками только помечаются (Печко и соавторы).
8. **Свежесть**: поток устарел, если не обновлялся дольше двух своих интервалов. Если интервала
   нет в словаре, он оценивается по данным (медиана шага) и это отмечается.
9. **Усреднённые по месяцам ряды** для обновления моделей (СТО Газпром 2-3.3-1203-2020), месяц по UTC.
10. **Отчёт о качестве**: доля строк без пропусков (всего и по потокам), доля пропусков по каждому
    параметру, число пометок по каждому критерию, свежесть потоков.

**Правила** (`src/field_twin/rules.py`), срабатывания пишутся в журнал (М8):

- **П13** «Устаревшие данные» — по результату проверки свежести; адресат — оператор пульта.
- **П14** «Расхождение связанных датчиков» — корреляция Пирсона пары датчиков по окнам (2 ч,
  решение прототипа) ниже порога. **Порог `min_pearson` в источниках не задан, поэтому правило
  выключено**, пока его не задать в `config/thresholds.yaml`.

## Что делает этап 3

**М5. Геотехника** (`src/field_twin/geotech.py`, Затырко и соавторы): класс каждого параметра
каждого пункта контроля относительно предела — зелёный (ниже 2/3), жёлтый (от 2/3 до предела),
красный (на пределе и выше); класс объекта — худший среди параметров (решение прототипа); тренд
осадки по датчикам и радару (только по ряду не короче 30 суток); неравномерность осадки; дата
последнего радарного замера. Предельные значения пунктов задаются в `config/tags.yaml`
(`attrs.limits`); в материалах их нет — в файле примерные значения, кроме 2 мм/м.

**Правила П2–П11** (`src/field_twin/rules.py`): П2–П4 — по оценке геотехники; П5 скорость газа,
П6 температура за турбиной Т-32, П7 снижение мощности и КПД за межремонтный период, П8 запас
устойчивости компрессора, П9 срок безопасной эксплуатации, П10 неработающая ЭХЗ, П11 пропуск
обслуживания ЭХЗ. Правила по рядам срабатывают один раз на эпизод нарушения, простои не
учитываются. Адресат П2–П11 настраивается (`configurable_recipient`).

## Что делает этап 4

**М3. Классификатор гидратов** (`src/field_twin/hydrates.py`, Сафронова): признаки — параметры
абсорбера и установки, расход метанола по точкам и их изменения за 1 шаг (2 мин) и за 200 шагов
(400 мин); CatBoost с подбором параметров через Optuna; выход каждые 2 минуты (1/0). Обучение — на
размеченных периодах и на причинах из журнала. После обучения печатаются матрица ошибок, точность,
полнота, F1 и доля правильных ответов рядом с ориентирами статьи. Деление выборки — по времени
(конец ряда на проверку).

**П1 и теневой режим** (`src/field_twin/notify.py`): предупреждение со звуком при 3 и более
положительных выходах за 20 минут, с действиями из статьи; одно предупреждение на серию, время от
первого срабатывания модели до предупреждения. В теневом режиме (`--shadow`) — запись в журнал без
звука и сравнение с фактом (`notify.shadow_comparison`). Каждый положительный выход модели пишется
в журнал.

## Что делает этап 5

**Экраны** (`src/field_twin/api.py`, `web/`): FastAPI и HTML без внешних библиотек и шрифтов,
звуковой сигнал — локальный файл `web/alarm.wav`. Две роли:

- **оператор пульта**: красная плашка П1 с действиями из статьи, звук до решения или квитирования,
  выходы модели гидратов, свежесть каждого потока (признак «устарел»), данные в реальном времени,
  три цвета состояния оснований, даты последних замеров (радар, ручные замеры ЭХЗ, обследования
  газопроводов), уведомления двойника и сигнализация АСУ ТП — в разных блоках;
- **главный инженер**: рекомендации и уведомления о ресурсе оборудования и газопроводов,
  оборудование, геотехника, даты замеров.

Решение (подтвердить или отклонить) обязательно с причиной из справочника и пишется в журнал (М8).

**Проигрывание архива** (`src/field_twin/playback.py`): записи CSV подаются в базу порциями по
времени данных, после каждой порции — цикл двойника. В журнал попадают только новые срабатывания:
эпизодное правило — один раз на эпизод, правило состояния — когда состояние возникло, П1 — один раз
на серию.

## Что делает этап 6

**М4. Модели Чудина** (`src/field_twin/chudin_models.py`): нейросеть ДКС (давления на входе и
выходе, расход → мощность и скорость вращения; 5 скрытых слоёв; Adam) и нейросеть
внутрипромыслового транспорта (10 входов → дебиты четырёх скважин; 1 скрытый слой из 4 нейронов;
Adam). Суточные данные, деление 60 / 40 % по времени, средняя относительная ошибка рядом с
ориентирами Чудина, дообучение на новых данных (`retrain`).

**Адаптация** (Еникеев, Топольников): на базовом периоде подбираются поправочные коэффициенты по
каждому выходу (метод наименьших квадратов), дальше они зафиксированы. **Связывающий алгоритм**:
на каждом шаге сначала считается транспорт, его дебиты передаются в модель ДКС.

**П15**: ошибка модели относительно замеров за последние 7 суток выше порога — сигнал главному
инженеру перекалибровать модель или проверить датчик. Порог в источниках не задан — правило
выключено, пока не задано `max_error_pct`.

Синтетическая физика (мощность ДКС от степени сжатия и расхода, дебит от перепада квадратов
давлений) нужна только для того, чтобы нейросетям было что учить; это не модели из источников.

## Что делает этап 7

**М9. Внешние расчётные ядра** (`src/field_twin/cores/`): единый интерфейс адаптера — передать
ядру текущие очищенные замеры, получить расчётные параметры и варианты режима. Ядра подключаются
строкой `модуль:Класс` в `config/cores.yaml`, поэтому заглушку можно заменить другим ядром без
правки кода. Сбой ядра не останавливает цикл двойника.

- `stub` — заглушка на синтетических данных: перераспределение газа между абсорберами при
  перекосе, увеличение подачи метанола перед А-2 при падении уровня в кубе;
- `aerosim` (АЭРОСИМ с «Интеллектуальным технологом», Войтенков) и `tnavigator` (ИРМ; Кулагин
  и соавторы) — пустые классы с описанием методов до получения лицензий и программных интерфейсов;
- `hysys` — **адаптер Aspen HYSYS** для заводской части (подготовка ПГ, сжижение, аммиак,
  карбамид): COM-автоматизация под Windows, соответствие сигналов и потоков модели в
  `config/hysys.yaml`, удельный расход энергии на тонну СПГ и рекомендация по нагрузке
  компрессоров хладагента. Как подключить — [`docs/hysys.md`](docs/hysys.md).

**П12**: каждая рекомендация ядра — уведомление главному инженеру (вид `recommendation` в
журнале), решение — подтвердить или отклонить с причиной.

## Что делает этап 8

**М10. Технологические остановки скважин** (`src/field_twin/stops.py`, Савченко и соавторы):
остановка — нулевой дебит газа; минимальная длительность 4 ч для высокопроницаемых и 12 ч для
низкопроницаемых объектов (класс скважины — `attrs.permeability` в `config/tags.yaml`, условный);
монотонный рост давления за время остановки (по сглаженному ряду, если сглаживание включено).
Подходящие остановки сохраняются в таблицу `well_stops` как кандидаты для оценки пластового
давления. Регрессии статьи выведены для нефтяных скважин — оценка давления не делается.

**М11. Стык с заводом** (`src/field_twin/plant_link.py`): сообщение «промысел → завод» по пяти
потокам (состав газа и C5+, объём газа, раздельные потоки, доступная мощность приводов, окна
снабжения и ремонтов) в JSON; обратное сообщение «завод → промысел» — формат, проверка и заглушка
с уведомлением главному инженеру. Раздельные потоки в данных прототипа не измеряются — поле пустое.

**П16**: остаток C5+ выше допуска завода. Порог задаёт пользователь (`max_c5plus_g_m3`); без него
правило выключено.

## Что делает этап 9

**Имитатор АСУ ТП** (`asu_simulator/`): сервер OPC UA с узлами по словарю параметров (значение,
признак качества, метка времени источника), история по каждому узлу (HistoryRead) и отдельная
архивная база, технологическая сигнализация по уставкам словаря (события OPC UA: LL, L, H, HH и
возврат в норму). Узлы только на чтение. Наполняется записями генератора.

**Шлюз М12** (`src/field_twin/gateway/`):

- `opcua_reader` — чтение текущих значений, архива и подписка на сигнализацию; методов записи нет;
  сверка узлов сервера со словарём (без привязки, отсутствующие, без уставок);
- `mqtt_reader` — приём сообщений удалённых объектов (тема `<prefix>/<поток>/<объект>/<параметр>`,
  JSON со значением, качеством, временем и состоянием); публиковать нельзя;
- `buffer` — буфер гарантированной доставки в SQLite: повторы отсекаются, запись помечается
  отправленной только после успешной передачи;
- `service` — основной и резервный источник с переключением; на каждом опросе дочитывается архив
  с последней принятой метки времени, поэтому ни между опросами, ни после обрыва связи ничего не
  теряется; сигнализация АСУ — в журнал отдельно (`source = asu`); в отчёт о приёме попадают
  сигналы без привязки и сигналы с незаполненными уставками;
- `manual_input` — ручной ввод (замеры ЭХЗ, анализы, исследования скважин) с пометкой «ручной»
  и теми же проверками;
- `execution_check` — после подтверждения рекомендации двойник по данным АСУ отмечает в журнале,
  изменился ли режим (в пределах допуска или хотя бы на полпути к предложенному).

Уставки в `config/tags.yaml` заданы только для трёх сигналов как пример (уровень в кубе А-2,
давление после сепаратора, температура за Т-32); остальные — незаполненные, как и должно быть до
получения перечня от владельца АСУ.

## Этап 11 (сверх ТЗ): модель КРН участков газопроводов

По статье Мирзоева, Иващенко, Маршакова (Вести газовой науки, 2016): 9 факторов грунта,
расположения и геотехники → многослойный перцептрон 10–13–2 → вероятность стресс-коррозии и
класс риска; правило П17 — уведомление главному инженеру запланировать шурф. Учтено:

- статья — о **магистральных** газопроводах; для **промысловых** прогноз помечен «вне области
  исходной модели»;
- применимость на каждом газопроводе подтверждается шурфами (≥ 10, совпадение ≥ 75 %); до этого —
  «ПРЕДВАРИТЕЛЬНО», при несовпадении — уведомлений нет;
- данных статьи нет — модель обучена на **синтетике**, и это написано в каждом прогнозе.

Подробно: [`docs/scc_model.md`](docs/scc_model.md).

Пример данных за сутки лежит в `data/samples/`.
