# Связь двойника с Aspen HYSYS

Модель завода в HYSYS (подготовка ПГ к сжижению с аминовой очисткой и адсорберами, сжижение
с теплообменниками LNG-100…103 и компрессорами K-100…K-107, производство аммиака, упрощённая
схема карбамида) подключается к двойнику как внешнее расчётное ядро М9 — так же, как АЭРОСИМ и
tNavigator. Код: `src/field_twin/cores/hysys.py`, настройки: `config/hysys.yaml`.

## Как работает

1. Двойник берёт последние очищенные значения промысла (М2): расход, давление и температуру газа,
   который уходит на завод.
2. Адаптер приостанавливает расчёт HYSYS (`Solver.CanSolve = False`), записывает значения во
   входной поток модели, включает расчёт и ждёт его окончания.
3. Читает результаты: массовые расходы СПГ, NH₃, карбамида, газа на сжижение и мощности
   компрессоров (энергопотоки Q-xxx).
4. Считает удельный расход энергии на тонну СПГ. Если он вырос относительно базового больше
   допустимого, формируется рекомендация «перераспределить нагрузку между компрессорами
   хладагента» (продольный разбор). Рекомендация идёт по общему пути: П12 → экран главного
   инженера → решение → журнал.

Двойник ничего не пишет в АСУ ТП; HYSYS — расчётная модель, а не источник управления.

## Что нужно на машине

- Windows с установленным и лицензированным Aspen HYSYS;
- Python 3.12 и пакет `pywin32` (`pip install pywin32`);
- файл модели `.hsc`, путь к нему — `case_path` в `config/hysys.yaml`.

Из облака и из Linux HYSYS не запускается: COM-автоматизация есть только под Windows. В тестах
адаптер проверяется на модели-заменителе (`FakeBackend`).

## Как включить

1. Открыть модель в HYSYS и выписать точные имена потоков: входной газ, газ на сжижение, СПГ,
   NH₃, карбамид, энергопотоки компрессоров. Вписать их в `config/hysys.yaml` (сейчас там имена
   со схемы и условные — `Feed`, `LNG`, `NH3`, `Urea`, `Q-100`…).
2. Проверить связь из Python:

   ```python
   import win32com.client
   app = win32com.client.Dispatch("HYSYS.Application")
   case = app.SimulationCases.Open(r"C:\models\plant.hsc")
   fs = case.Flowsheet
   print(fs.MaterialStreams.Item("LNG").MassFlow.GetValue("tonne/h"))
   print(fs.EnergyStreams.Item("Q-100").HeatFlow.GetValue("kW"))
   ```

   Имена свойств (`MassFlow`, `StdGasFlow`, `Pressure`, `Temperature`, `HeatFlow`) и единиц
   соответствуют распространённым версиям HYSYS; если версия отличается, поправить их в
   `config/hysys.yaml`, код менять не нужно.
3. Задать базовый удельный расход энергии и допустимый рост (`recommendations.specific_energy`).
4. Включить ядро: `enabled: true` у `hysys` в `config/cores.yaml`.

## Другие способы связи

| Способ | Когда |
| --- | --- |
| COM-автоматизация (реализовано) | стационарная модель, расчёты «что будет, если» по текущим замерам |
| OPC через динамический режим (HYSYS Dynamics, надстройки вроде Aspen OTS) | если модель динамическая и нужен «виртуальный завод» или тренажёр; тогда HYSYS подключается к шлюзу М12 как ещё один сервер OPC UA |
| Aspen Simulation Workbook (Excel) | только для ручных расчётов |

## Что ещё можно брать из модели

- обратный поток «завод → промысел» (М11): допустимый приём газа при ремонте линии;
- риск вымерзания тяжёлых углеводородов: расчёт по составу газа и остатку C5+ (П16);
- доступная мощность приводов для обоих двойников.
